Sourcing Workflow

The path from a new role to sent outreach, and which Sourcing Intelligence command helps at each step.

The steps

  1. Prep for kickoff. Confirm the role has a folder in the Role Launches folder in Google Drive and that its job description is there. Check whether your role is in the shared Sourcing Rubrics doc. If not, add it or ask Erica.
  2. Build the strategy. Run /sourcing-strategy for a rubric, a 4-tier company shortlist, five priority candidate signals, compensation research, and a Hiring Feasibility Review (Green, Yellow, or Red).
  3. Calibrate after meetings. Run /update-rubric after every kickoff and hiring sync. Paste in notes or a Granola transcript and it updates the living rubric with a dated change log entry.
  4. Check the dossier. When a req opens, run /dossier to look for people already flagged as a fit before starting a fresh search.
  5. Source. Run /source-batch with a cap you set (for example 15, 20, or 30). It evaluates each candidate against the rubric and sends a Slack summary when done.
  6. Make assets. Run /create-asset for role info pages, one-pagers, "Why CodePath" pieces, Loom scripts, and candidate FAQs.
  7. Draft and send outreach. Follow the outreach standards. A human reviews every message before it goes out.
  8. Track results. Use Greenhouse tracking links to see which sources work, and watch the Sourcing Pulse dashboard for daily stats.

Director and above: pre-check first

For any candidate at Director level or above, the plugin does a public research pass before drafting outreach. It looks for conference talks, blog posts, course authorship, GitHub activity, podcast appearances, and press mentions, then picks a hook to lead with. You see a short summary and can redirect the angle before the full draft.

Pre-check: [Name]
Hook found: [What was found and where]
Outreach angle: [How it will be used]
Proceeding to draft.

Open-ended asks also work

  • Evaluate a candidate: "Can you evaluate [Name] for the Director of Growth role?"
  • Draft outreach: "Write an InMail for [Name]" or "Draft a 3-step sequence for the PM role."
  • Deep research pass: "Do a deep research pass for the Sr. Director of Curriculum."
  • Comp research: "What's the market rate for a Director of Growth in edtech?"
  • Proactive list building: "Start building a list for a future Head of Product role."

Where files are saved

Everything goes to the Sourcing Strategy folder in Google Drive, in a subfolder named [YourName]_[Role Title], for example Erica_Director of Growth.

FileWhat it contains
sourcing-rubric.md + .docxLiving rubric, updated after every hiring sync
company-shortlist.md + .docx4-tier target company list with rationale
candidate-signals.md + .docxPriority signals for identifying ideal candidates
sourcing-strategy.md + .docxStrategy summary including HFR, channels, selling points
batch-log.mdRunning log of every sourcing batch run
outreach-copy/Outreach drafts for the role
assets/One-pagers, info pages, Loom scripts
deep-research-candidates.md + .docxNamed candidates surfaced through deep research

The shared _pipeline/talent-dossier.md sits at the top level of the Sourcing Strategy folder, not inside a role subfolder.

Data governance

  • Juicebox project naming: name of the role = name of the project. Each role gets its own project.
  • New sources in Greenhouse: to add an entirely new source, contact Dom Terry first to avoid duplicates. Tracking links show where candidates come from: Tracking Link Setup in Greenhouse.
